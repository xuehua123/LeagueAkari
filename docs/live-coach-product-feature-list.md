# League Akari 实时语音 AI 教练：一、二、三期产品功能清单

> 文档类型：纯产品功能 WBS
> 文档版本：v1.0
> 最后更新：2026-08-25
> 产品基准：小地图是空间事实的核心依据；死亡、装备、游戏时间和已发生目标事件等明确列出的对局状态只能作为辅助信息
> 配套文档：[产品方案与技术实施基线](./live-coach-three-phase-plan.md)

## 0. 文档说明

这份文档只回答一件事：产品最终要给用户提供哪些功能。

清单按照以下层级组织：

1. 一期、二期、三期；
2. 每一期包含若干“大项目”；
3. 每个大项目继续拆成“子项目”；
4. 每个子项目下面是可以排期、设计和验收的具体产品功能。

本文件不包含代码结构、接口设计、算法伪代码、模型实现或研发技术选型。相关内容见 [技术实施基线](./live-coach-three-phase-plan.md)、[P0 技术决策](./live-coach-p0-technical-decisions.md) 与 [开发交付规格](./live-coach-development-spec.md)。

### 0.1 研发范围标记

- **必做**：除红线外的全部功能都必须实现、完成测试并保留可运行能力；
- **红线**：永久不开发；
- 审核、地区、设备、版本和运营状态只控制对外用户能否看到功能，不影响开发排期、内部测试或功能完成定义。

范围标记写在大项目标题中，其下所有子项目和功能点默认继承该标记。所有现有大项目均为必做；对外开关与研发范围分离。

### 0.2 产品信息边界

- **当前小地图**：本人、友方、当前可见敌人、粗粒度区域、聚集、移动趋势等空间事实的唯一核心依据；
- **辅助对局状态**：游戏时间、本人及队伍存活状态、死亡与复活、装备状态、已发生的击杀和目标事件等；这些信息必须单独显示来源；
- **历史与用户信息**：历史对局、个人画像、用户自述和训练目标只能作为背景，不能覆盖当前小地图事实；
- 所有直接空间观测必须能够回到对应的小地图画面；不可见敌人的位置、路线与意图可以由小地图观察、last-seen、移动趋势、地图路径和允许的辅助状态共同推断；
- 辅助状态不能脱离小地图证据单独生成战争迷雾结论；所有推断必须标注为预测，展示概率、依据、有效时间和可能误差；
- 每条提示和回答都要区分“小地图当前可见、辅助对局状态、历史背景、用户自述”；
- 小地图不可用时停止地图级位置、路线、迷雾和宏观空间判断；第三期完整画面的近身战斗/微操分析可按独立证据继续，但不能冒充小地图宏观事实；
- 因此，“以小地图为准”不等于“产品只能读取小地图”，而是“小地图负责空间事实，其他信息只在明确范围内辅助解释”。

### 0.3 三期产品关系

| 阶段   | 产品名称       | 用户得到的核心价值                         | 主要产品形态                                           |
| ------ | -------------- | ------------------------------------------ | ------------------------------------------------------ |
| 第一期 | 小地图守望者   | 发现小地图变化，预测迷雾风险并指导购买装备 | 离线录像分析、迷雾预测、装备指导、短语音、字幕、悬浮窗 |
| 第二期 | 小地图态势教练 | 把地图变化组织成风险、资源和阶段任务       | 情景提示、最多两个选项、证据卡片、关键时刻复盘         |
| 第三期 | 全模态主动教练 | 用户可以追问、获得主动指挥并长期训练       | 多种语音输入、授权音频、全画面分析、主动指挥、多模式   |

## 1. 第一期：小地图守望者

### 1.1 本期产品目标

第一期解决五个问题：

- 能稳定找到并读取小地图；
- 播报当前确实看见、仍然有效的重要变化；
- 推断不可见敌人的概率区域、路线、到达时间和可能意图；
- 根据金币、已有装备、阵容、局势和补丁给出购买装备指导；
- 用户可以清楚知道功能是否运行、为什么提醒、如何暂停和删除数据。

真实对局中的实时采集、实时分析和局内输出均为必做。审核未完成或失败时，仅在外部版本关闭对应入口；项目负责人内部测试与研发构建继续保留完整非红线能力。

### P1-M04 大项目：基础小地图观察【必做】

#### P1-M04-S01 子项目：可见单位识别

- [ ] 识别本人在小地图上的位置；
- [ ] 识别当前可见的友方英雄；
- [ ] 识别当前可见的敌方英雄；
- [ ] 识别当前小地图上的可见人数变化；
- [ ] 无法确认具体英雄时显示为“友方单位”或“敌方单位”；
- [ ] 不确定时保留“不确定”状态；
- [ ] 图标短暂被遮挡时不立刻反复报错；
- [ ] 图标重新出现时更新为新的可见观察；

- [ ] 不把预测位置继续当作当前直接观测，单独展示概率区域和有效时间。

#### P1-M04-S02 子项目：区域识别

- [ ] 将小地图位置转换为上半区、河道、下半区等粗区域；
- [ ] 区分己方野区、敌方野区和中立区域；
- [ ] 区分主要资源附近区域；
- [ ] 区域无法确认时只显示位置变化，不强行命名；
- [ ] 显示观察发生的时间；
- [ ] 显示观察是否已经过期；
- [ ] 对区域边界附近的图标避免频繁来回切换；
- [ ] 地图方向变化后保持区域名称正确。

#### P1-M04-S03 子项目：聚集与变化

- [ ] 识别某一区域同时出现多名当前可见敌人；
- [ ] 识别某一区域当前可见人数明显增加；
- [ ] 识别高优先级的小地图变化；
- [ ] 识别多个可见单位短时间内向同一区域靠近；
- [ ] 同时输出可见几何变化和经过独立阈值验证的敌方意图预测；
- [ ] 相同变化持续存在时不重复创建新事件；
- [ ] 变化已经结束时及时结束事件；
- [ ] 可信度不足时不生成正式提醒。

#### P1-M04-S04 子项目：观察记录

- [ ] 为每条观察保留发生时间；
- [ ] 为每条观察保留地图区域；
- [ ] 为每条观察保留单位类别；
- [ ] 为每条观察保留可信程度；

- [ ] 显示观察来自当前画面还是其他已允许信息；
- [ ] 允许用户在赛后查看本局观察时间线；
- [ ] 过期观察在界面中明确变灰；
- [ ] 不允许过期观察继续触发新提醒。

## 3. 第三期：全模态主动教练

### 3.1 本期产品目标

第三期让用户从“被动接收提醒”升级到“可以追问、可以主动指挥、可以逐帧训练、可以复盘、可以长期训练”：

- 用户能围绕证据询问“刚才为什么提醒”；
- 用户能通过文本、按键说话、唤醒词或常开麦控制教练；
- 教练能在授权下综合完整游戏画面、系统声音和队伍沟通提供主动战术指挥；
- 教练能覆盖逐帧微操、其他地图/模式和观战场景；
- 教练回答始终区分当时事实、当前事实和赛后信息；
- 产品根据多局可验证表现形成个人训练计划。

离线赛后证据问答、多种语音输入、实时回答、授权音频、全画面分析、主动指挥和动态语音均为第三期必做；审核状态只控制外部版本的显示与启用。

## 4. 跨期公共能力归属

本节不是第四份重复功能清单，只说明公共产品能力首次在哪一期交付、以后在哪个大项目继续增强。同一个功能只以“主归属大项目”为排期和验收入口。

| 公共能力                       | 首次交付 | 后续增强                                     | 主归属                         |
| ------------------------------ | -------- | -------------------------------------------- | ------------------------------ |
| 产品入口与首次引导             | 第一期   | 二、三期增加新能力说明                       | P1-M01                         |
| 教练总开关、模式、类别和快捷键 | 第一期   | 二期增加态势模式，三期增加对话控制           | P1-M08、P2-M10                 |
| 小地图标定与支持范围           | 第一期   | 二期扩展分辨率、显示环境和识别范围           | P1-M03、P2-M01                 |
| 语音、提示音和字幕             | 第一期   | 三期增加 PTT/唤醒词/常开、授权音频和云端声音 | P1-M06、P3-M02、P3-M10         |
| 悬浮窗                         | 第一期   | 二期增加任务与证据，三期增加收音和问答状态   | P1-M07、P2-M09                 |
| 会话摘要与复盘资料             | 第一期   | 二期增加关键时刻，三期增加问答和长期报告     | P1-M10、P2-M12、P3-M01、P3-M09 |
| 用户反馈                       | 第一期   | 二期增加提示反馈，三期增加回答纠错           | P1-M10、P2-M11、P3-M13         |
| 数据导出、删除和保留           | 第一期   | 三期增加麦克风、云端、画像和授权数据         | P1-M11、P3-M12                 |
| 地区、版本和可用状态           | 第一期   | 三期增加服务分项状态与降级                   | P1-M12、P3-M14                 |
| 按位置和英雄的偏好             | 二期     | 三期升级为个人画像和训练计划                 | P2-M10、P3-M07、P3-M08         |
| 产品公告、灰度和客服入口       | 第一期   | 二期增加质量反馈，三期增加 AI 服务状态       | P1-M12、P2-M14、P3-M14         |

公共能力遵循以下归属规则：

- 用户只看到一个教练设置中心，各期项目只向同一入口增加设置项；
- 数据删除以 P1-M11 和 P3-M12 为唯一主入口，其他页面只跳转或带入预选范围；
- 会话资料以 P1-M10、P2-M12 和 P3-M01 的递进形态展示，不创建互不相通的三套历史记录；
- 悬浮窗沿用同一个用户入口和位置设置，二、三期只增加状态与交互；
- 同一用户反馈只提交一次，再由对应阶段页面展示处理结果；
- 后续增强不得重新打开用户已经关闭的权限、提醒类别或云端能力。
