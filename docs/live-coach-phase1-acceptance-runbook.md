# 实时语音 AI 教练：第一期验收执行手册

> 用途：第一期代码完成后，项目负责人按本手册收集真实证据、判断是否达到发布线。
> 原则：审核只控制外部开启；内部构建、离线回放和 Shadow 验证继续进行。

## 1. 当前可自动完成的验收工作

应用会在本机自动维护第一期验收台账，并在“实时教练 → 诊断”显示进度：

- 真实 Shadow 对局数量与时长；
- 唯一离线录像/Sidecar 的导入成功数量与时长；
- 每条提示的规则版本、状态、有效期，以及提示生成当时仍存在的同会话 current evidence 验证；
- 提示反馈标注覆盖率和错误提示频率；
- ROI 独立会话启动/每次重新标定 episode 的首次健康成功率；
- 采集延迟、推理延迟、frame age、采集 FPS、应用 CPU 和工作集；
- 异常退出、采集错误和会话结束原因。

验收台账只保存哈希后的会话、提示和证据 ID，不保存原始画面、录像、麦克风音频、召唤师名称或完整文件路径。用户可以随时导出或清空。

## 2. 内部验收构建

使用内部构建，确保审核状态不会阻塞项目负责人自用测试：

```powershell
yarn build:win:internal
```

安装或解压后先检查“实时教练 → 诊断”：

- WGC 或 DDA 至少一个显示可用；
- 实时采集能力可用；
- 当前补丁、地图和队列满足一期范围；
- 小地图 ROI 能进入 `healthy`；
- 模型状态不是哈希错误、报告错误或补丁不匹配。

`desktopCapturer` 只用于一次性标定和诊断，使用它完成的会话不计入有效 Shadow 对局。

## 3. 身份模型数据与发布门禁

真实 ROI 数据集不进入 Git。先运行不依赖 PyTorch 的数据审计：

```powershell
python tools/live-coach-ml/audit_identity_dataset.py `
  --dataset-root D:\live-coach-data `
  --manifest D:\live-coach-data\manifests\dataset-v1.jsonl `
  --patch <当前完整补丁号> `
  --output D:\live-coach-data\reports\dataset-audit.json
```

退出码含义：

- `0`：数据契约和全部发布数据门禁通过；
- `1`：清单、授权、哈希、路径、标注复核或集合隔离无效；
- `2`：数据有效但数量或覆盖矩阵不足。

只有训练报告 `decision=accepted`、许可证状态经负责人审核为 `approved`、许可证告知文件哈希有效、worker 协议兼容、运行时 manifest 的 `releaseEligible=true`，且模型、报告、数据集哈希完全一致时，才能把模型复制到 `resources/live-coach/models/`。Bootstrap 模型只用于运行时冒烟，不能作为正式身份识别模型。内部 Windows 构建还会逐文件校验 FFmpeg 与原生插件，并实际启动 FFmpeg/FFprobe、加载采集与语音插件；任一步失败都会阻断产物。

## 4. 100 局离线回放

在“实时教练 → 录像复盘”逐局导入本人有处理权的录像或合法 Sidecar：

- 至少 100 个不同内容哈希的成功回放；
- 重复导入同一文件不会增加唯一回放数量；
- 导入失败会记录格式和错误码，但不计入成功数量；
- 每局检查标定、时间轴、提示时间、跳转、取消、摘要和导出；
- 对关键视觉事件建立独立 ground truth，不能用程序自己的输出充当真值。

完成后在诊断页确认“唯一离线回放”为 `100 / 100`，并导出一期验收报告留档。

## 5. 50 局真实 Shadow

在“实时教练 → 教练设置”开启 Shadow 模式。此模式必须完整运行采集、识别、规则和调度，但不播放声音、不显示局内字幕和悬浮提示。

每局有效 Shadow 必须同时满足：

- 来源是真实游戏，不是 `manual_` 或 `internal_` 模拟会话；
- 召唤师峡谷，单局至少 5 分钟；
- 后端为 WGC 或 DDA；
- ROI 在本局至少一次进入 `healthy`；
- 没有为了凑数量拆分或重复同一局。

每局结束后在主界面检查该局提示记录，并把所有提示标记为“有用”或“错误”；“太晚”和“太频繁”可以同时用于体验分析，但不能替代正确性标注。提示标注覆盖率达到 95% 后，错误提示频率门禁才会给出通过或失败结论。

完成后应看到：

- 有效 Shadow 对局 `50 / 50`；
- Shadow 累计时长至少 100 小时；
- 提示证据可追踪率 100%；
- ROI 启动成功率在至少 50 个独立会话启动/重新标定 episode 中达到 99%；同一局多次重标必须分别计入分母。应用台账只提供保守点估计，正式放行还必须按对局聚类计算 95% 置信下界并达到 99%，不得用相邻 episode 伪装成独立样本。

## 6. 仍需真实设备或人工真值的项目

以下项目不能由仓库夹具或程序自报结果替代，诊断页会保持“待验证”：

- 可见事件 Precision/Recall、粗区域准确率、坐标误差和关键漏报；
- `false-healthy` 人工复核及单侧 95% 置信上界；
- 开关教练前后的成对 CPU、GPU、工作集、VRAM 基准；
- 游戏 1% low FPS 影响；
- 首帧、确认、首音、端到端和取消延迟的 ground-truth 对齐；
- Windows 10/11、1080p/1440p、100%/125%/150% DPI、左右小地图、窗口/无边框的支持矩阵；
- 100 小时无泄漏、异常退出、helper crash-loop 和恢复测试；
- 当前补丁的独立回归批准与外部开启结论。

这些报告必须记录设备、系统、补丁、分辨率、DPI、窗口模式、采集后端、样本量、统计方法、原始证据哈希和复核人。任何停止线命中时，立即关闭对应实时能力并保留诊断证据。
